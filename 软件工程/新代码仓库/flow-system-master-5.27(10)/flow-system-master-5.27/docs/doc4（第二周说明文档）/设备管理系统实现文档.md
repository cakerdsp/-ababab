# 设备管理系统实现文档

## 概述

本文档描述了Flow-System客户端后端设备管理系统的实现，包括设备控制、传感器数据管理、实时通信和数据分析等核心功能。

## 系统架构

### 架构设计原则

1. **分层架构**: 采用领域驱动设计(DDD)，分为领域模型、业务逻辑、基础设施服务三层
2. **单一职责**: 每个类和模块都有明确的职责边界
3. **依赖注入**: 通过构造函数注入依赖，便于测试和维护
4. **事件驱动**: 使用SSE实现实时数据推送和状态同步

### 包结构

```
src/class/
├── Domain Models (领域模型)
│   ├── Device.js          # 设备基础模型
│   ├── Sensor.js          # 传感器模型
│   └── HistoryData.js     # 历史数据模型
├── Business Logic (业务逻辑)
│   ├── DeviceManager.js   # 设备管理器
│   ├── DataManager.js     # 数据管理器
│   └── DeviceController.js # 主控制器
└── Infrastructure (基础设施)
    ├── SSEService.js      # SSE实时通信服务
    ├── AccountAPIRegistry.js # API注册器
    └── AccountStorage.js  # 存储服务
```

## 核心功能模块

### 1. 设备管理模块

#### Device 类 (设备基础模型)

**职责**: 
- 设备基础属性管理
- 设备控制操作验证
- 设备状态更新

**主要功能**:
- **设备属性管理**: 统一管理设备ID、名称、类型、品牌、在线状态等
- **控制验证**: 根据设备类型验证控制指令的合法性
- **状态管理**: 提供设备状态读取和更新接口

**验证规则**:
- **空调**: 温度范围16-30°C，风速档位验证，模式验证
- **加湿器/除湿器**: 湿度范围30-80%，模式验证
- **空气净化器**: 风扇等级1-3级，模式验证

#### Sensor 类 (传感器模型)

**职责**:
- 继承设备基础功能
- 传感器数据特殊处理
- 支持的指标类型管理

**主要功能**:
- **数据验证**: 温度(-10~60°C)、湿度(0~100%)、PM2.5(0~500μg/m³)
- **时间戳管理**: 自动添加数据采集时间
- **指标类型识别**: 根据传感器类型返回支持的指标

#### DeviceManager 类 (设备管理器)

**职责**:
- 设备生命周期管理
- 设备状态同步
- 设备控制操作

**主要功能**:
```javascript
// 初始化设备管理器
await deviceManager.initialize();

// 获取设备列表
const devices = deviceManager.getAllDevices();
const xiaomiDevices = deviceManager.getDevicesByBrand('Xiaomi');

// 控制设备
const result = await deviceManager.controlDevice('device123', 'power', 'ON');

// 处理实时更新
deviceManager.handleDeviceUpdate(sseData);
```

### 2. 数据管理模块

#### HistoryData 类 (历史数据模型)

**职责**:
- 24小时历史数据存储
- 数据统计计算
- 趋势分析

**主要功能**:
- **数据管理**: 自动维护24小时数据窗口
- **统计计算**: 平均值、最值、数据点数量
- **趋势分析**: 基于最近6小时数据计算上升/下降/稳定趋势

#### DataManager 类 (数据管理器)

**职责**:
- 传感器历史数据管理
- 环境数据分析
- 数据刷新和同步

**核心分析功能**:
```javascript
// 环境数据分析
const analysis = dataManager.analyzeEnvironmentData(['sensor1', 'sensor2']);

// 分析结果包含
{
  temperature: {
    average: 25.5,
    min: 22.0,
    max: 28.5,
    trend: 'rising'
  },
  humidity: {
    average: 55.2,
    min: 45,
    max: 65,
    trend: 'stable'
  },
  pm25: {
    average: 35.8,
    min: 25,
    max: 48,
    airQuality: 'good'
  },
  comfort: {
    level: 'very_good',
    score: 85,
    factors: [...]
  }
}
```

**舒适度评估算法**:
- **温度评估**: 最适宜20-26°C，可接受18-28°C
- **湿度评估**: 最适宜40-60%，可接受30-70%
- **空气质量**: PM2.5 ≤35优秀，≤75良好，≤115中等
- **综合评分**: 基础100分，根据偏离程度扣分

### 3. 实时通信模块

#### SSEService 类 (SSE服务)

**职责**:
- 与服务端建立SSE长连接
- 实时数据接收和分发
- 连接状态管理和重连

**主要功能**:
- **连接管理**: 自动连接、断线重连(最多5次)
- **消息分发**: 根据消息类型分发给不同处理器
- **错误处理**: 完善的错误处理和日志记录

**消息类型**:
- `realTime`: 实时设备状态更新
- `history`: 传感器历史数据更新
- `message`: 其他类型消息

### 4. 主控制器

#### DeviceController 类 (设备控制器)

**职责**:
- 协调各个管理器
- 提供统一的业务接口
- 系统初始化和资源管理

**初始化流程**:
1. 设置用户ID和SSE连接ID
2. 初始化设备管理器(加载所有设备状态)
3. 初始化数据管理器(加载传感器历史数据)
4. 建立SSE连接
5. 注册消息处理器

**资源清理**:
- 通知服务端退出SSE连接
- 断开SSE连接
- 重置所有管理器状态

## API接口设计

### 设备相关API

| API路径 | 方法 | 功能 | 参数 |
|---------|------|------|------|
| `/devices/status` | GET | 获取所有设备状态 | JWT Token |
| `/device/control` | POST | 设备控制 | `{did, control: {operation, value}}` |

### 传感器数据API

| API路径 | 方法 | 功能 | 参数 |
|---------|------|------|------|
| `/api/sensor-data/last24h` | GET | 获取24小时历史数据 | `device_id`, `metric_type` |

### SSE相关API

| API路径 | 方法 | 功能 | 参数 |
|---------|------|------|------|
| `/events` | GET | 建立SSE连接 | `sseconid` |
| `/api/sse/exit` | POST | 退出SSE连接 | `{sseconid}` |

## IPC接口设计

### 设备管理IPC

```javascript
// 获取所有设备
const devices = await window.electronAPI.invoke('get-all-devices');

// 根据品牌获取设备
const devices = await window.electronAPI.invoke('get-devices-by-brand', 'Xiaomi');

// 控制设备
const result = await window.electronAPI.invoke('control-device', {
  did: 'device123',
  operation: 'power',
  value: 'ON'
});

// 获取设备控制选项
const options = await window.electronAPI.invoke('get-device-control-options', 'device123');
```

### 数据分析IPC

```javascript
// 获取传感器历史数据
const history = await window.electronAPI.invoke('get-sensor-history', 'sensor123', 'temperature');

// 分析环境数据
const analysis = await window.electronAPI.invoke('analyze-environment-data', ['sensor1', 'sensor2']);

// 刷新所有数据
const result = await window.electronAPI.invoke('refresh-all-data');
```

### 系统状态IPC

```javascript
// 获取系统状态
const status = await window.electronAPI.invoke('get-system-status');

// 重连SSE
const result = await window.electronAPI.invoke('reconnect-sse');
```

## 数据流设计

### 设备控制流程

1. **前端发起控制** → IPC调用 → DeviceController
2. **参数验证** → Device.validateControl()
3. **发送控制指令** → AccountAPIRegistry → 服务端API
4. **状态更新** → SSE推送 → DeviceManager.handleDeviceUpdate()

### 传感器数据流程

1. **初始化加载** → DataManager.loadSensorHistory()
2. **实时更新** → SSE推送 → DataManager.handleSensorUpdate()
3. **数据分析** → DataManager.analyzeEnvironmentData()

## 错误处理策略

### 网络错误处理

- **API调用失败**: 返回标准错误格式，包含错误码和消息
- **SSE连接断开**: 自动重连机制，最多尝试5次
- **超时处理**: 设置10秒API超时，3秒重连延迟

### 数据验证错误

- **设备控制验证**: 客户端和服务端双重验证
- **传感器数据验证**: 范围检查和类型验证
- **用户友好提示**: 详细的错误消息和操作建议

## 性能优化

### 内存管理

- **设备状态缓存**: 使用Map结构高效管理设备状态
- **历史数据清理**: 自动清理超过24小时的数据
- **连接资源管理**: 及时释放SSE连接和清理事件监听器

### 并发处理

- **并行数据加载**: 同时加载多个传感器的历史数据
- **异步操作**: 所有API调用都是异步的，不阻塞UI
- **批量处理**: 支持批量设备操作和数据刷新
