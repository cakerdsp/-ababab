
一：环境历史数据存储设计
1.0 流程说明
服务端：每次获得第三方推送的设备数据时，检查是否是传感器数据。再检查是否应该采样（每小时采样一次），采样时将传感器数据更新在数据库中，并且将更新后的最新24h数据传给客户端
客户端：初始化时获取全部传感器24h数据（刷新按钮也是这样），后面接收推送更新，更新内存数据和页面
 
1.1	要求
简化：只存储24h数据
1.2	服务端数据库表设计
CREATE TABLE sensor_hourly_data (
    device_id VARCHAR2(64) NOT NULL,      -- 设备ID
    metric_type VARCHAR2(32) NOT NULL,    -- 指标类型(temperature/humidity/pm25)
    hour_start TIMESTAMP NOT NULL,        -- 小时起始时间(精确到小时)
    metric_value NUMBER(10,2) NOT NULL,   -- 指标值
    CONSTRAINT pk_sensor_hourly PRIMARY KEY (device_id, metric_type, hour_start)
);

-- 创建时间索引
CREATE INDEX idx_sensor_hourly_time ON sensor_hourly_data(hour_start);
1.3	服务端行为
1.3.1	收集采样传感器数据
1.	在美的设备回调接口和小米设备回调接口检测是否是传感器设备 isSensor
2.	如果是传感器数据，调用handleSensorUpdate函数，完成传感器数据在数据库中的存储, 这里后面新增了历史数据推送，具体见1.3.3
 
3.	具体更新逻辑：
在2023-08-20 14:30收到设备123的温度数据26.5：
	将时间转为2023-08-20 14:00:00
	检查表中是否已有设备123、温度指标、14:00的记录
a)	如果有：更新值为26.5
b)	如果没有：插入新记录
	删除所有早于2023-08-19 14:30的记录
