# 🔐 第三方授权功能实现指南 (正确架构版本)

## 📋 概述

本文档详细说明第三方品牌授权的正确实现方案，严格遵循Electron架构：
**渲染进程(UI) → IPC通信 → 主进程 → class业务逻辑**

## 🏗️ 正确的架构设计

```
┌─────────────────┐    IPC调用    ┌─────────────────┐    方法调用    ┌─────────────────┐
│                 │ ──────────── │                 │ ──────────── │                 │
│   渲染进程       │               │    主进程       │               │  AccountManager │
│  (Vue组件)      │ ←──────────── │   (index.js)    │ ←──────────── │    业务类       │
│   UI状态管理     │    进度回调    │   IPC处理器     │    结果返回    │   HTTP请求      │
└─────────────────┘               └─────────────────┘               └─────────────────┘
```

## 🎯 功能需求

- **两步骤授权**: 获取授权码 → 绑定账号
- **严格分层**: UI层、IPC层、业务逻辑层分离
- **HTTP请求**: 严格按照授权码相关api.md实现
- **进度反馈**: 主进程向渲染进程发送实时进度
- **错误处理**: 完整的异常处理机制

## 🔧 详细实现

### 1. AccountAPIRegistry.js - 统一API管理

**新增API端点**:

#### 1.1 授权码API配置
```javascript
getAuthorizationCode: '/mockapi/auth/getAuthorizationCode', // 第三方授权码获取API
bindWithAuthCode: '/auth/code', // 使用授权码绑定API
```

#### 1.2 特殊API方法
```javascript
// 获取授权码 - 使用相对路径，不带基础URL
async getAuthorizationCode(data)

// 使用授权码绑定 - 自动处理token认证
async bindWithAuthorizationCode(data)
```

**实现要点**:
- 使用axios统一HTTP客户端
- 自动处理JWT Token认证和刷新
- 统一的错误处理和响应格式
- 支持不同基础URL的API调用

### 2. AccountManager.js - 核心业务逻辑

**新增方法**:

#### 1.1 获取授权码方法
```javascript
/**
 * 获取第三方品牌授权码 - 严格按照API文档实现
 * @param {string} userId - 用户ID
 * @param {string} brandName - 品牌名称 (xiaomi, midea)
 * @returns {Promise<Object>} 授权码获取结果
 */
async getAuthorizationCode(userId, brandName)
```

**实现要点**:
- 使用统一的API调用方式 `this.apiRegistry.getAuthorizationCode()`
- 严格按照API文档请求格式
- 完整的错误处理和状态码检查

#### 1.2 授权码绑定方法
```javascript
/**
 * 使用授权码绑定第三方品牌账号 - 严格按照API文档实现
 * @param {string} authCode - 授权码
 * @param {string} brandName - 品牌名称
 * @returns {Promise<Object>} 绑定结果
 */
async bindWithAuthorizationCode(authCode, brandName)
```

**实现要点**:
- 使用统一的API调用方式 `this.apiRegistry.bindWithAuthorizationCode()`
- JWT Token认证（由AccountAPIRegistry自动处理）
- 自动更新本地绑定状态

#### 1.3 完整授权流程方法
```javascript
/**
 * 完整的第三方品牌授权流程 - 两步骤：获取授权码 → 绑定账号
 * @param {string} brandName - 品牌名称
 * @returns {Promise<Object>} 授权结果，包含进度回调
 */
async performThirdPartyAuthorization(brandName, progressCallback)
```

**实现要点**:
- 协调两个步骤的执行
- 通过progressCallback发送进度更新
- 统一的错误处理

### 3. main/index.js - IPC处理器

**新增IPC处理器**:

#### 2.1 完整授权流程处理器
```javascript
ipcMain.handle('perform-third-party-authorization', async (event, brandName) => {
  // 调用AccountManager的完整授权流程
  // 使用event.sender.send发送进度更新到渲染进程
})
```

#### 2.2 单独方法处理器（可选）
```javascript
// 获取授权码
ipcMain.handle('get-authorization-code', async (event, userId, brandName) => {})

// 使用授权码绑定
ipcMain.handle('bind-with-authorization-code', async (event, authCode, brandName) => {})
```

### 4. ThirdPartyAuth/index.vue - UI组件

**修改要点**:

#### 3.1 删除HTTP请求逻辑
- 移除所有fetch调用
- 移除业务逻辑处理

#### 3.2 IPC通信实现
```javascript
// 确认授权 - 通过IPC调用主进程业务逻辑
async confirmAuth() {
  const result = await window.ipcRenderer.invoke('perform-third-party-authorization', this.brandName);
}
```

#### 3.3 进度监听器
```javascript
mounted() {
  // 监听主进程发送的授权进度更新
  window.ipcRenderer.on('third-party-auth-progress', this.handleProgressUpdate);
}

beforeUnmount() {
  // 清理IPC监听器
  window.ipcRenderer.off('third-party-auth-progress', this.handleProgressUpdate);
}
```

## 🔄 数据流程

### 完整授权流程

1. **用户操作**: 点击账号中心的"立即绑定"
2. **页面跳转**: 跳转到ThirdPartyAuth页面
3. **用户确认**: 点击"授权"按钮
4. **IPC调用**: 渲染进程调用`perform-third-party-authorization`
5. **主进程处理**: 调用AccountManager.performThirdPartyAuthorization
6. **业务执行**:
   - 获取授权码 (progress: 25%)
   - 绑定账号 (progress: 75%)
   - 完成 (progress: 100%)
7. **进度更新**: 主进程发送`third-party-auth-progress`事件
8. **UI更新**: 渲染进程更新进度条和状态
9. **结果处理**: 成功后跳转回账号中心

### 进度回调机制

```javascript
// 主进程发送进度
event.sender.send('third-party-auth-progress', {
  step: 'getAuthCode',
  progress: 25,
  message: '获取授权码中...'
});

// 渲染进程接收进度
window.ipcRenderer.on('third-party-auth-progress', (event, progress) => {
  this.updateUI(progress);
});
```

## ⚠️ 重要说明

### 架构优势
1. **职责分离**: UI、IPC、业务逻辑各司其职
2. **可维护性**: 业务逻辑集中在class中易于维护
3. **可测试性**: 可以独立测试AccountManager的方法
4. **安全性**: 渲染进程无法直接访问网络和文件系统

### 注意事项
1. **服务器依赖**: 当前API调用会失败，需要服务器支持
2. **Token管理**: 确保JWT Token的正确获取和使用
3. **错误处理**: 完善的网络错误和业务错误处理
4. **进度反馈**: 确保UI能够正确显示授权进度
