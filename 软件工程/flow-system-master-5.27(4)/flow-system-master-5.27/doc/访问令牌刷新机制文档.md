# Flow System 访问令牌刷新机制文档

## 概述

本文档详细描述了 Flow System 应用中访问令牌的自动刷新机制，包括触发条件、刷新流程和具体实现细节。

## 访问令牌刷新机制架构图

```
API请求发起
      ↓
请求拦截器添加Bearer Token
      ↓
发送请求到服务器
      ↓
[服务器返回401] → 响应拦截器捕获
      ↓
检查是否有refreshToken
      ↓
[有] → 调用刷新令牌API
      ↓
[刷新成功] → 保存新token → 重新发送原请求
[刷新失败] → 返回错误，可能需要重新登录
```

**行号**: 42-68

```javascript
// 添加响应拦截器处理token过期
this.client.interceptors.response.use(
  response => response,
  async error => {
    if (error.response?.status === 401 && this.storage) {
      // token过期，尝试刷新
      const refreshToken = this.storage.getRefreshToken();
      if (refreshToken) {
        try {
          const refreshResponse = await this.refreshAccessToken(refreshToken);
          if (refreshResponse.success) {
            // 重新发送原请求
            error.config.headers['Authorization'] = `Bearer ${refreshResponse.data.token}`;
            return this.client.request(error.config);
          }
        } catch (refreshError) {
          console.error('Token刷新失败:', refreshError);
        }
      }
    }
    return Promise.reject(error);
  }
);
```

### 2. 刷新令牌API实现

**文件**: `src/class/AccountAPIRegistry.js`

#### 2.1 刷新访问令牌方法

**行号**: 143-174

```javascript
// 刷新访问令牌
async refreshAccessToken(refreshToken) {
  try {
    const response = await this.client.post(this.apiPaths.refreshToken, {
      refreshToken: refreshToken
    });

    if (response.data.status === 'success') {
      // 保存新的token
      if (this.storage) {
        this.storage.saveToken(response.data.data.token);
      }
      return {
        success: true,
        data: response.data.data
      };
    } else {
      return {
        success: false,
        message: response.data.message
      };
    }
  } catch (error) {
    console.error('刷新token失败:', error);
    return {
      success: false,
      message: '刷新token失败'
    };
  }
}
```

### 8. Token过期触发场景

#### 8.1 API调用时自动触发

当任何需要认证的API调用返回401状态码时，响应拦截器会自动触发刷新机制。

**常见触发场景**:

- 获取绑定信息: `GET /auth/bindings`
- 绑定第三方品牌: `POST /auth/code`
- 解绑第三方品牌: `POST /auth/unbind`

#### 8.2 自动登录时主动检查

在应用启动的自动登录流程中，如果发现token不存在或验证失败，会主动调用刷新机制。

- **401 Unauthorized**: refreshToken无效或已过期

## 机制特点

### 1. 自动化

- **无需用户干预**: 整个刷新过程对用户透明
- **无缝体验**: 原API请求在token刷新后会自动重试

### 2. 安全性

- **有效期管理**: 访问令牌短期有效，刷新令牌长期有效
- **失败清理**: 刷新失败时自动清除所有本地认证数据

### 3. 容错性

- **多层检查**: 在自动登录和API调用中都有刷新机制
- **错误处理**: 完善的错误日志和用户提示

### 4. 性能优化

- **拦截器实现**: 使用Axios拦截器实现，性能高效
- **按需刷新**: 只在需要时才进行token刷新
