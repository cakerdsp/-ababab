# 离线调试模式手册

本文档说明如何使用新实现的离线调试模式。此模式允许您在没有连接到后端服务器的情况下测试应用程序的UI和数据处理逻辑。

## 如何激活离线模式

1.  启动应用程序。
2.  在登录界面，输入以下凭据：
    *   **用户名:** `admin`
    *   **密码:** `admin`
3.  点击登录按钮。
4.  应用程序将**自动重启**。这是正常现象。
5.  重启后，应用程序将处于离线调试模式。所有数据都将从您项目目录中的本地文件读取和保存。

## 工作原理

当您以`admin`身份登录时，应用程序会创建一个临时标志文件并重新启动。重新启动时，它会检测到此标志，将其存储系统重定向到本地文件夹 (`/debug-storage`)，然后删除该标志。

所有后续操作（查看设备、分组等）都将使用位于 `/debug-storage` 目录中的JSON文件。在此模式下，用于实时更新的SSE连接是禁用的。

## 编辑本地数据以模拟更改

要测试UI如何响应数据更改，您可以手动编辑 `/debug-storage` 目录中的JSON文件。

*   **设备列表:** `debug-storage/flow_system_devices.json`
*   **分组列表:** `debug-storage/flow_system_groups.json`

**示例：模拟设备状态更改**

1.  打开 `debug-storage/flow_system_devices.json`。
2.  找到您想要修改的设备，例如 `"did": "dev_123_offline"`。
3.  更改其状态。例如，将 `"power": "on"` 更改为 `"power": "off"`。
4.  保存文件。
5.  由于数据不会从磁盘热重载，您需要**刷新应用程序窗口**（例如，如果开发工具已打开，可使用 `Ctrl+R` 或 `Cmd+R`）或离开设备页面再返回，才能看到更改生效。应用程序在服务初始化时加载此数据。对于某些数据，完全重启应用程序可能是查看更改最简单的方法。

## 退出离线模式

要退出离线模式并再次连接到服务器，只需从 `admin` 帐户**登出**，然后使用您的常规用户凭据登录。应用程序将正常运行，连接到远程服务器。您也可以直接重启应用程序。由于调试标志在使用后即被删除，任何正常的重启都会使应用程序返回在线模式。
