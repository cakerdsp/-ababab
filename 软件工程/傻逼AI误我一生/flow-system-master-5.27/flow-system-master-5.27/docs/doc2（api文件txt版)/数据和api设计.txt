2.	美的api设备状态变化推送设计
2.1说明
1.	参考：https://mis.midea.com/docs/control-midea-cloud-devices/cloud-2-cloud-thing-api.html#_5-5-9-%E5%B1%9E%E6%80%A7-properties-%E8%AE%BE%E7%BD%AE2.
2.	 流程说明：
a)	需要美的云端服务的app要提前在美的注册自己服务端接受美的推送的接口。模拟实现时，本系统服务端就需要预留一个接口api“notify”给美的模拟api，美的模拟api可以发送设备变化信息到notify上给本系统
b)	美的需要有个设备订阅接口，本服务器传递设备id给美的，后面该设备有状态变化则推送到上面注册的接口notify上
2.2	设备订阅请求接口api
请求头：Authorization（根据查询资料得这个令牌就是access token）,ClientId(应用id)
请求方式：post
请求地址：建议midea/device/subscribe （具体要看前面第三方模拟的习惯，记得不一致需要更改该文档）
请求参数：reqId (请求id)， applianceCode(设备虚拟id)
返回结果：reqId（请求id）
错误码：1300设备不存在，1006 用户验证失败（就是token不对）
2.3	设备取消订阅接口
其实和设备订阅接口长的一样，但是要分开两个api地址
请求头：Authorization（根据查询资料得这个令牌就是access token）,ClientId(应用id)
请求方式：post
请求地址：建议/device/subscribe/ /cancel（具体要看前面第三方模拟的习惯，记得不一致需要更改该文档）
请求参数：reqId (请求id)， applianceCode(设备虚拟id)
返回结果：reqId（请求id）
错误码：1300设备不存在，1006 用户验证失败（就是token不对）
2.4	消息通知接口api （应用服务端实现api，美的提前知道地址且需要调用地址并且推送通知）
具体看服务端api设计（只需要看请求体格式和路径），美的需要实现一个函数推送设备数据变化给服务端api
简化设备数据变化：
除了传感器的设备只需要一个初始状态，平时不需要变化，只有后面实现了控制时，控制设备变化，就推送
传感器写个脚本使传感器数据在合理范围内随意波动即可，然后推送
3. 小米api设备状态变化推送设计
3.1  说明
1. 参考: https://iot.mi.com/new/doc/accesses/direct-access/other-platform-access/control-api 事件类api
2. 流程说明：流程类似美的，但是本系统接收消息的api不是一开始就被小米所知，而是需要附带在设备订阅请求接口api上
3.2  设备订阅请求接口
请求方式：post
请求地址：建议midea/device/subscribe （具体要看前面第三方模拟的习惯，记得不一致需要更改该文档）
请求头：access_token. App_id(应用id)
请求参数：（设备id）did， app接收消息的地址"receiver-url“
返回结果：200成功
错误码：001设备不存在，903授权过期

3.3 设备取消订阅接口
和设备订阅接口类似，但是请求地址和参数有变化
请求方式：post
请求地址：建议midea/device/subscribe/cancel （具体要看前面第三方模拟的习惯，记得不一致需要更改该文档）
请求头：access_token. App_id(应用id)
请求参数：（设备id）did
返回结果：200成功
错误码：001设备不存在，903授权过期
3.4 消息通知接口api（应用服务端实现api，小米根据receiver-url推送通知）
具体看服务端api设计（只需要看请求体格式和路径），小米需要实现一个函数推送设备数据变化给服务端api
简化设备数据变化：
传感器之外的设备只需要一个初始状态，平时不需要变化，只有后面实现了控制时，控制设备变化后，就推送
传感器写个脚本使传感器数据在合理范围内随意波动即可，然后推送
4. 实现建议
用数组记录被订阅的设备id，取消订阅和增加订阅都对数组更改即可
推送设备状态变化可以不用持久化设备状态（就是不用数据库建表），运行时就写个函数，对数组内的传感器随便变化，然后推送
后续实现控制设备时，控制设备属性改变时，顺便推送新的设备变化

1.3 设备消息推送
1. 和客户端建立连接的初始化，提供sse连接入口
  ssetoken就是userid
 （心跳机制可以省略）

Sse连接api说明
建立服务器推送（SSE）长连接，用于向客户端实时推送设备状态变更（如温湿度传感器数据、设备开关状态等）。
请求路径：GET /events
请求头：无要求
请求参数：sseconid
响应头：错误码403， sseconid无效 500服务器内部错误
 
2.	消息推送就是在提供给第三方的api函数上实时处理，一收到第三方的推送，就将did和data提取出来，通过sse连接发送出去（参照1,2的图）。具体推送给客户端的标签和格式需要小米美的统一，服务端决定，决定后告知客户端
建议：data: {"did":"设备ID", "power":"ON", "temperature":26}\n\n
1.4 客户端主动退出接口
	路径：POST /api/sse/exit

	功能描述
用户主动通知服务端终止SSE连接，触发服务端清理以下资源：

取消该用户所有设备的第三方订阅（如美的/小米API）
关闭SSE长连接
移除内存中的连接记录
	请求参数：sseconid（就是userid）
	响应码：204退出成功，404连接不存在或者已经关闭
这里取消设备订阅就是调用第三方的取消设备订阅接口，取消该用户的所有设备订阅
 


2	客户端
登录后需要存储 sseconid
初始化先拉取全部设备状态，存储在内存，建立和服务端的sse连接
 
获得推送时，改变前面内存里面的状态
 
退出程序或者退出登录时，调用退出api
