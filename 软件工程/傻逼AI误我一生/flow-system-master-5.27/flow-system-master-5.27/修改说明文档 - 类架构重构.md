# 设备管理系统类架构重构说明文档

## 概述

本次修改对原有的设备管理系统进行了全面的重构，采用了分层架构设计模式，提高了代码的可维护性、扩展性和复用性。重构后的系统采用了Domain-Driven Design (DDD) 的思想，将代码组织为多个独立但协作的模块。

## 架构层次结构

```
src/class/
├── domain/          # 领域层 - 数据模型和核心业务实体
├── modules/         # 模块层 - 业务逻辑管理器
├── services/        # 服务层 - 基础设施服务
└── index.js         # 入口文件 - 统一导出和向后兼容
```

## 详细架构说明

### 1. Domain层（领域层）

负责定义核心业务实体和数据模型，包含：

- `UserAccount` - 用户账户实体
- `SupportedBrand` - 支持的品牌实体  
- `Device` - 设备基础实体
- `Sensor` - 传感器设备实体（继承自Device）
- `HistoryData` - 历史数据实体

### 2. Modules层（模块层）

负责业务逻辑管理，采用单一职责原则分为以下管理器：

#### 2.1 设备管理模块 (`modules/device/`)

- **DeviceRegistry** - 设备注册表（单例模式）
  - 管理所有设备的注册、注销和索引
  - 按品牌、类型、在线状态等维度建立索引
  - 提供设备查询、统计等功能

- **DeviceStatusManager** - 设备状态管理器
  - 管理设备的实时状态同步
  - 处理SSE推送的设备状态更新
  - 集成本地存储缓存机制
  - 从服务端获取并维护最新设备状态

- **DeviceController** - 设备控制器
  - 提供设备控制操作接口
  - 验证控制指令的合法性
  - 支持单设备和批量设备控制
  - 支持设备场景执行

- **GroupManager** - 分组管理器
  - 设备分组的创建、删除、更新
  - 支持自定义分组和自动分组（按品牌、类型）
  - 维护设备与分组的双向映射关系
  - 支持分组级别的设备控制

#### 2.2 数据管理模块 (`modules/data/`)

- **HistoryDataManager** - 历史数据管理器
  - 管理传感器的24小时历史数据
  - 处理SSE推送的历史数据更新
  - 提供环境数据分析和报告生成
  - 支持多种数据分析维度（温度、湿度、PM2.5等）

#### 2.3 账户管理模块 (`modules/account/`)

- **AccountManager** - 账户管理器
  - 用户登录、认证管理
  - API注册表管理
  - 支持的品牌管理

#### 2.4 系统级管理器

- **SystemManager** - 系统管理器（核心协调器）
  - 统一的系统初始化入口
  - 协调各个子管理器的工作
  - 提供完整的系统级API接口
  - 管理SSE连接和消息处理

### 3. Services层（服务层）

提供基础设施服务：

#### 3.1 存储服务 (`services/storage/`)

- **UnifiedStorage** - 统一存储服务
  - 文件系统存储封装
  - 内存缓存机制（5分钟过期）
  - 支持用户数据、设备数据、分组数据等存储
  - 提供数据导入导出功能

#### 3.2 API服务 (`services/api/`)

- **AccountAPIRegistry** - API注册器
  - 统一的API调用接口
  - 请求/响应处理
  - 错误处理和重试机制

#### 3.3 SSE服务 (`services/sse/`)

- **SSEService** - Server-Sent Events服务
  - 实时数据推送接收
  - 消息分发和处理
  - 连接管理和重连机制

## 核心设计模式

### 1. 单例模式
- `DeviceRegistry` 使用单例模式确保全局唯一的设备注册表

### 2. 策略模式
- 设备类型根据不同类型采用不同的处理策略

### 3. 观察者模式
- SSE服务通过观察者模式分发消息到各个管理器

### 4. 代理模式
- 入口文件提供向后兼容的代理接口

## 向后兼容性

为了保证现有代码不受影响，在 `index.js` 中提供了：

1. **兼容的接口包装器**
   ```javascript
   const deviceController = {
     // 代理到SystemManager的方法
     async initialize(userId) { ... },
     getAllDevices() { ... },
     // ... 其他方法
   };
   ```

2. **便捷方法集合**
   ```javascript
   module.exports = {
     // 设备相关便捷方法
     device: { ... },
     // 分组相关便捷方法  
     group: { ... },
     // 历史数据相关便捷方法
     history: { ... },
     // 系统相关便捷方法
     system: { ... }
   };
   ```

## 使用示例

### 基础使用（向后兼容）
```javascript
const { deviceController, stateManager } = require('./src/class');

// 初始化系统
await deviceController.initialize(userId);

// 获取所有设备
const devices = deviceController.getAllDevices();

// 控制设备
await deviceController.controlDevice('device_id', 'power', 'ON');
```

### 新架构使用
```javascript
const { systemManager, device, group, history } = require('./src/class');

// 初始化系统
await systemManager.initialize(userId);

// 使用便捷方法
const devices = device.getAll();
const groups = group.getAll();
const sensorData = history.getAll();

// 创建分组
group.create({
  name: '客厅设备',
  deviceIds: ['device1', 'device2']
});

// 分析环境数据
const analysis = history.analyze(['sensor1', 'sensor2']);
```

## 迁移指南

现有代码无需修改即可使用，新功能建议使用新的API接口：

1. **设备管理** - 使用 `device.*` 便捷方法
2. **分组管理** - 使用 `group.*` 便捷方法  
3. **历史数据** - 使用 `history.*` 便捷方法
4. **系统管理** - 使用 `system.*` 便捷方法
