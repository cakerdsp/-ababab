# TurtleBot3 地图一致性和初始位置修复说明

## 问题诊断

用户报告了三个主要问题：
1. **地图不一致**：Gazebo中显示的障碍物与rviz中的地图不匹配
2. **初始位置不固定**：Gazebo每次启动时机器人位置不是从(0,0)开始
3. **坐标系疑问**：rviz中机器人似乎"钉在中心"，询问这是否正常

## 修复方案

### 1. 地图一致性问题修复

**问题根源**：
- Y轴坐标转换错误：ROS地图和图像坐标系的Y轴方向相反
- 像素坐标计算错误，导致障碍物位置偏移
- 随机种子未固定，每次生成不同的障碍物布局

**修复内容**：
- **修复了`spawn_obstacles.py`中的坐标转换逻辑**
- **正确处理Y轴翻转**：ROS地图Y轴向上为正，图像Y轴向下为正
- **添加固定随机种子**：确保每次生成相同的障碍物布局
- **改进障碍物检测**：避免重叠和距离原点太近的障碍物

**具体修改**：
```python
# 修复前的错误转换
grid_y = int((y + MAP_HEIGHT/2) / RESOLUTION)

# 修复后的正确转换
grid_y = int((MAP_HEIGHT/2 - y) / RESOLUTION)  # Y轴翻转
```

### 2. 初始位置固定修复

**问题根源**：
- launch文件未强制指定机器人初始位置
- Gazebo保存了之前的世界状态
- 缺少重置机制

**修复内容**：
- **修改launch文件**：明确设置机器人初始位置参数
- **添加清理脚本**：清除Gazebo临时文件和旧地图
- **创建重置服务**：`reset_robot.py`可强制重置机器人位置
- **优化启动顺序**：确保各组件按正确顺序启动

**具体修改**：
```xml
<!-- 在固定位置生成机器人 -->
<node pkg="gazebo_ros" type="spawn_model" name="spawn_urdf" 
      args="-urdf -model turtlebot3_burger -x 0.0 -y 0.0 -z 0.0 -Y 0.0 -param robot_description"/>
```

### 3. RViz坐标系说明

**答案**：您的观察是正确的！
- **Fixed Frame设置为"map"是正确的**
- 机器人"钉在中心"的现象在某些视角下是正常的
- 这表示坐标系配置正确：地图是固定的，机器人在地图上移动

**改进**：
- 更新了rviz配置文件，添加了机器人模型显示
- 改用俯视图视角，更适合2D路径规划
- 添加了TF显示，可以清楚看到坐标系关系

## 技术细节

### 坐标系转换
- **世界坐标系**：X轴向右，Y轴向上，原点在中心
- **图像坐标系**：X轴向右，Y轴向下，原点在左上角
- **转换公式**：
  ```python
  grid_x = (world_x + MAP_WIDTH/2) / RESOLUTION
  grid_y = (MAP_HEIGHT/2 - world_y) / RESOLUTION  # 注意Y轴翻转
  ```
