## 项目框架

整个项目包含两个包，tracking_pid是一个ROS路径跟踪器的实现，其内部主要实现了两个模块：路径插值器和跟踪控制器。路径插值器接受通过话题/path传来的路径信息，将进行插值后的轨迹点发布到/trajectory话题中。跟踪控制器接受轨迹点的信息通过PID控制器生成下一步的速度，发布速度命令到话题/move_base/cmd_vel。

mobile_robot_simulator是用于模拟的，其中的激光雷达模块在当前的测试中并没有使用。其订阅路径跟踪器发送的速度指令，然后更新里程计和坐标转换的信息。运行时ROS节点话题关系图如下：

## PID代码实现

在控制器中实现PID代码，目前代码中实现了误差计算、使用二阶低通滤波器过滤误差信号的高频噪声、以及对误差积分项和差分项的更新。现在只要将配置中读取的参数与对应的项相乘相加，同时依据配置添加前馈控制项，最后对输出进行限幅，防止信号过大导致系统不稳定。实现代码如下：

```cpp
// 计算纵向PID控制
  if (feedback_long_enabled)
  {
    proportional_long = Kp_long * filtered_error_long.at(0);
    integral_long = Ki_long * error_integral_long;
    derivative_long = Kd_long * filtered_error_deriv_long.at(0);
    control_effort_long = proportional_long + integral_long + derivative_long;
  }
  if (feedforward_long_enabled)
  {
    control_effort_long += feedforward_long;
  }

  // 计算横向PID控制
  if (feedback_lat_enabled)
  {
    proportional_lat = Kp_lat * filtered_error_lat.at(0);
    integral_lat = Ki_lat * error_integral_lat;
    derivative_lat = Kd_lat * filtered_error_deriv_lat.at(0);
    control_effort_lat = proportional_lat + integral_lat + derivative_lat;
  }
  if (feedforward_lat_enabled)
  {
    control_effort_lat += feedforward_lat;
  }

  // 计算角度PID控制
  if (feedback_ang_enabled)
  {
    proportional_ang = Kp_ang * filtered_error_ang.at(0);
    integral_ang = Ki_ang * error_integral_ang;
    derivative_ang = Kd_ang * filtered_error_deriv_ang.at(0);
    control_effort_ang = proportional_ang + integral_ang + derivative_ang;
  }
  if (feedforward_ang_enabled)
  {
    control_effort_ang += feedforward_ang;
  }

  // 应用控制输出限制
  if (control_effort_long > upper_limit)
    control_effort_long = upper_limit;
  if (control_effort_long < lower_limit)
    control_effort_long = lower_limit;
  if (control_effort_lat > upper_limit)
    control_effort_lat = upper_limit;
  if (control_effort_lat < lower_limit)
    control_effort_lat = lower_limit;
  if (control_effort_ang > ang_upper_limit)
    control_effort_ang = ang_upper_limit;
  if (control_effort_ang < ang_lower_limit)
    control_effort_ang = ang_lower_limit;
```

## PID调参

PID由三项组成，比例向是误差直接乘以比例系数组成。这是系统直接响应误差的项，当比例系数大时，系统对误差的响应快，比例系数小时，系统对误差的响应慢。

$$
u_p(t) = K_p e(t)
$$

微分项是误差的微分乘以微分系数组成。它可以预测误差的变化趋势，相当于综合了未来的信息。当偏差开始出现变化时，微分项就能提前产生控制作用，从而抑制偏差的进一步增大。但是，微分项对噪声比较敏感。如果测量信号中存在噪声，微分项会对噪声的高频成分产生较大的放大作用，从而影响控制效果。

$$
u_d(t) = K_d \frac{de(t)}{dt}
$$

积分项是误差的积分乘以积分系数组成。它综合了误差的历史信息，积分项能够对偏差在时间上的积累进行补偿。随着时间的推移，即使偏差很小，积分作用也会不断累积，从而产生足够的控制作用来消除稳态误差。不过，积分项可能会导致系统超调增加。因为积分作用的累积效应，当偏差消除后，积分环节可能还会产生较大的控制作用，使被控量超过设定值。

$$
u_i(t) = K_i \int_{0}^{t} e(\tau) d\tau
$$

在调参界面中的l表示控制点位于机器人前方0.5单位距离，适用于前轴横向控制。也就是说控制点与机器人保持一段距离，这规定了拐弯特性，在拐角处不可能会完美贴合绿色路径。

单独调整lat的积分项结果如下，可以看到与之前的效果没多大差别，因为lat方向没有固定的误差，累积的那点误差对整个路径规划没有太大影响：

![1748051951164](image/22320021_陈安康_第二次作业/1748051951164.png)

综上分析lat方向的微分项的影响，发现其主要影响体现在拐弯的时刻，不引入lat的积分项和微分项时，在拐弯处，lat的速度是匀速的，拐弯点在中间。当引入微分项时，在控制点拐弯后，lat的误差微分增大，机器人在lat方向的速度更大，机器人会更及时的跟随控制点，当控制点完成拐弯，进入直道，误差微分变小，对机器人在lat方向上的速度起抑制作用，使其快速转向。由于在lat方向的速度是从大到小，会导致拐弯点更偏“左”，从而更加贴合目标路径。

综上，我得到了如下信息：角度的比例项在过大时会出现转弯过早的现象，过小时会出现转弯过大的现象，需要慎重调节。为了消除l带来的稳态误差，我需要引入long的积分项。在拐弯处如果不引入lat的微分项，拐弯点会在中间，当引入lat的微分项，由于速度受到微分项影响导致拐点改变，更加贴近目标路径。
